# 视觉系统

数值为起点，参考图片不是源 PPT，不能声称辨认出准确字号与字体。先确定字体性格、信息几何和场景体量，再定数值。

## 角色驱动的色板与背景节奏

先分清输入用途：身份图锁定角色，配色/风格参考提供整页色彩关系，真实案例截图保留证据原色。用户明确要求优先；没有明确色号但提供配色参考时，分析其整页关系并与角色协调，而不是先让衣服最大色块覆盖参考。只有身份图时，从角色主要色彩家族建立候选方案；多人或多色IP可保留有作用的第二色，不按总像素面积消掉另一角色。排除参考板底色、叠加文案、水印、肤色和无关细节对取色的干扰；白、近黑等中性色可作为重要空间角色，不因取彩色而忽略。`assets/default-theme.json` 的蓝系仅作无输入候选。

学习配色至少说明四件事：颜色分别承担什么角色、谁占大面积谁只点缀、明度/饱和度与冷暖如何形成主次、这些关系如何跨页变化。分别确定页面背景、景色/环境、标题/正文、强调信息与保留的角色原色。近似色合并，精确色号可从参考采样后微调保证可读；目测值注明近似，不能把显示采样当原稿标准色。颜色数由关系决定，不机械把所有颜色搬入，也不强制单色深浅阶。参考有互补/邻近配色时可以继承；需说明作用并控制大色面的竞争。蓝衣角色可以与暖色强调或中性底协调，不要求每样物件都变蓝。

在项目的 palette_contract 中记录 source_kind（explicit / visual-reference / character-derived / content-derived / fallback）、source_refs、roles、rationale、page_strategy。roles 至少包含 background、environment、text、accent，每项写 colors（#RRGGBB 列表）、source 和 usage，允许同色承担不同角色；另说明角色与证据原色如何保留。source_refs 记录路径与用途；显式色号和纯内容推导可不含图片，无输入fallback不冒充参考吸收。展示方向时说明主要角色和色彩关系，不额外增加一轮取色审批。

同套允许亮底、深底、主色色面、景色底切换，依内容密度、情绪和章节作用安排；跨页共享颜色角色，面积比例可以变化。小正文保持足够明度反差，亮色主要用于大字或少量重点；截图不染色，身份图不因调色改衣。生图提示词和原生对象引用同一套已选色彩角色。最终看目标端截图中的整体关系、角色与背景协调、重点和阅读对比，不能只比一个主色或检查“全是蓝色”。原有间距与对齐标准在不同底色上一样有效。

## 字体先分工，再做展示设计

将文字分为主字体（封面/页标题）、辅字体（副标题/组标题）和说明字体（正文/图注/注释），不按“中文/英文”分工。未另有用户指定时，从 `assets/font-groups.json` 的 B、C 两组选择，整套保持同一组；字体配置以该文件为准。不能用“换宋体”或“全用粗黑体”替代字号、行长、断行和场景关系的设计，也不为增加变化在各页随意切换字体组。

| 字体组 | 主字体 | 辅字体 | 说明字体 |
|---|---|---|---|
| B · 书刊叙事 | 思源宋体 Heavy | 阿里巴巴普惠体3.0 SemiBold | 阿里巴巴普惠体3.0 Light |
| C · 创意表达 | 得意黑 Oblique | 阿里巴巴普惠体3.0 SemiBold | 阿里巴巴普惠体3.0 Light |

根据角色图的气质、线条/体块、服饰语言、姿态与情绪选择，不按肤色、性别或“真人=B、卡通=C”机械分类：沉静、知性、优雅、细腻或偏书卷气的角色优先 B；轻快、俏皮、外向、动势明显或夸张轮廓的角色优先 C。2D、3D与真人都可能适用任一组，角色颜色本身不决定字体。多人按共同气质与主要叙事选择；无明显方向时按内容决定，仍难区分时用 B。选择写明图中可见依据，在原有视觉方向确认中一起展示，不新增字体审批；用户明确指定优先。

两组说明文字均用 Light 300，不额外 bold；浅底默认 `#454B54`，比主标题降低视觉重量，不用纯黑。深底默认 `#D9DDE3`，不能继续用深灰造成低对比。实际小字号或复杂背景下细笔画不清楚时，先改善承载背景、字号与行距，仍不足才对受影响的小文字升为 Regular 400并记录原因，不把整套说明字改粗。说明字体承担长阅读，不等于一律缩成小注释；正文仍沿用18–24的起始区间。主/辅文字的颜色继续由项目色板决定。

| 任务 | 中文与英文的关系 | 页面机制 |
|---|---|---|
| 有张力的主题/封面 | 依内容气质选有性格的展示字；中英各有信息职责 | 保留完整语义，再决定是否拆词、错位或穿插；没有用途时不加大英文 |
| 编辑叙事/观点 | 沿用选定的 B/C 组；主字有性格，说明字轻而清楚 | 用字面、笔画反差与精确断行，不临时另换字体组 |
| 方法/资料/截图说明 | 中等或粗黑组标题 + 稳定阅读正文；数字易区分 | 标签、表格、步骤和留白组织信息，正文不做实验性拆字 |
| 强调关键词/短句 | 同一字体的粗细、正斜、大小或疏密反差 | 一个主要处理即可，不把同句做成多种字效拼盘 |

中英搭配看可见字面、粗细、基线与整体黑度，不只给中英相同字号。中文连续阅读保持完整字形和语义词组；英文展示字可调整大小写、字宽/字距与断行，但不可拉伸到笔画明显畸变。平台不支持字距或字体特性时，可将短展示词分成原生文本框手动定位；正文不逐字拆。中文句末标点不孤立出现在行首，打开/关闭括号及中西混排需复核实际换行。

960×540 的常规标题可从38–64起步，极短展示词可到72–140；正文18–24，次级标签13–16。数值按用途和字面调整，不靠缩字装下全文。展示字与正文各自使用合适的行距，通常正文1.25–1.45；标题不机械继承正文的宽松行距。

拆解设计是可选手段，先保留自然语义、词组关系和标点归属；不把逗号单独悬在远处，不让跳跃的字号/基线打断句义，不用大写英文的面积填空。需要局部遮挡/切片时保留阅读顺序和关键笔画。原生词组保持可编辑；必须转曲或图像的特殊字形单独交代，并保留原生可读副本，不能声称每一笔可编辑。普通文字之间仍不得意外重叠；有意字形组合记录 text_treatment、分组和遮挡对象，保留完整词义于备注供核对。

本机字体存在不证明飞书有同款。制作阶段核对所选组的三种角色、实际字重和中英回退；工具不支持数值字重时，选实际的 Heavy/SemiBold/Light 字体面，不用合成加粗冒充指定字重。缺字体时用目标端可用的同类字形并说明替代与影响，保留主/辅/说明的分工；截图核对字形、换行和浅灰细字可读性，不能静默退回全篇同一种黑体，也不能把文字转成图片假称原生。安装阶段不遍历所有字体；字体文件不打包进通用 Skill。字体研究与边界见 [字体研究](typography-research.md)。

不同引擎的字号/坐标单位不能混用；按实际画布比例转换，不能把px直接当pt。

## 景色层参与构图

联合设计“页面底色 → 景色/空间 → 角色 → 原生信息 → 必要前景”的层序；可以缺层，不能只有抠图人物反复贴左右。从角色分析的环境/道具词汇与本页内容共同选择场景，例如办公室局部、桌面活动、建筑空间或内容相关的自然环境。独立景色不生成舞台、展台、高台、厚底座、悬浮平台或带截面底板的地形/微缩景色；不能以“工作台”“纸面地形”为名变相生成台座。正常桌椅可使用，但须符合角色世界与实际支撑。普通信息几何用原生对象，具象场景用图像素材。

先给场景一个与本页内容相关的作用：角色在整理什么、比较什么、检查什么，或用明确隐喻连接步骤与观点；再定体量与位置。默认小人、2D/3D IP与真人都采用这一联合构图；按角色协议选择符合媒介的身体/表情表现与空间，不只给真人造景。趣味可来自任务困境、物件尺度、协作反应或角色与信息的前后穿插，不能依靠随机表情或道具填空。仅能解释为“更活泼”“摆造型”“有景色”的场景不够，优先移除或重构。不要为了“有景”堆树、云、光圈或无关小物件。角色与场景共享镜头、透视、地面和光向，角色、桌椅和物件有可解释的支撑与接触；阴影只加强接触，不替代承托关系。拼贴也不能让家具/人物无依据漂浮。真实截图保持清楚，不被造景盖住。

背景景色、人物和必要前景可独立成图层；复杂抓握/坐姿等接触可以合并为一个语义素材，避免强拆导致手、道具或影子对不上。标题、正文与数据始终单独原生化。用裁切、前后遮挡和大小反差连接角色与信息，不把所有页面压成全屏写实房间。

## 景色边界与自然衔接

生成前就按最终PPT位置决定每条边如何收尾。场景、家具、背景和辅助元素不能与页底形成突兀的矩形拼接、竖直切口或水平断带；人物、桌板和地面不能被切成悬空片段。可用连续环境延伸至页外、完整且可信的物体轮廓、合乎情境的前景遮挡，或仅对环境氛围做局部透明过渡。需要补绘延展时保留构图与身份；人物、手、任务物件和证据内容保持清晰，不将全图羽化或四角圆化当成自然融合。

图像文件框、alpha包围框和最终可见边界分开判断。alpha紧裁不能保证自然衔接：文件边缘的不透明内容若在画内结束，仍会露出切口。真实截图、设备外框和原生信息卡片按内容保留可辨轮廓；不要为消除场景接缝而模糊证据。家具的内部结构线可以存在，但桌沿不能成为画内戛然而止的底边/横条；家具需有支撑、合理遮挡或向页外延展。不能把“物理桌沿”当作悬空板和硬切口的豁免。

物件可跨出PPT页边，正常版心边距不限制有意出血的景色。需要延伸的桌面/地面就让它与最终页边连续，不为给页码或注释预留底色条而把桌板切断在画内；页码另找可读位置。文件自带截边也不能直接拿来当自然轮廓。逐素材记录 support_relation 与 edge_treatment，出血同时沿用 bleed_objects，脸、手、语义动作与关键证据仍在安全区域。

在PPT实际截图中检查画内接缝与色差，尤其是底色不同、场景缩放或反复裁切后的左右边缘。保留源图和处理参数；局部背景过渡不改变已确认的人物与文案。

## 间距、对齐与可见轮廓

先建立页面 spacing_system。960×540 的默认主间距只用四档：tight=8（标题到正文）、related=16（同一信息组）、group=24（独立组）、outer=40（外边距与主要列沟）。这是起点，参考有明确节奏时可换一套；单页主间距档位不超过四个，同语义关系用同一个 token。4 单位仅可用于胶囊内部微调，不另造主体间距档位。不要把行距/字距与模块间距混为一类，也不要求所有空白都一样。

- 先按信息分组，画出阅读顺序与对齐对应关系。每个独立文字、数字、角色、信息框或设备，尽可能至少与一个其他元素或语义组共享左/右缘、中心、上下缘或基线；孤立装饰必须解释其作用，不能让一句说明漂在无归属的位置。
- 对齐不等于全页统一左对齐：例如数字与抬头、下方第一组共左缘，角色与另一信息组共中心，组内正文再各自左对齐。先分析关系再选轴，避免为机械对齐破坏语义分组。用“组内近、组间远”建立层级。
- 文本框按实际断行和字体测量，不用宽大的空文本框充当内容宽度；文本框的安全余量保留，但图文位置要按可见文字判断。
- 图片按 alpha 可见包围框与人物轮廓判断，数字按实际字形而非空文本框判断。中心对齐先测可见框中心，再按身体主质量做少量光学校正；伸出的手、头饰可能偏移几何中心。记录校正理由，不能声称包围框中心就是视觉中心。透明文件边缘不能充当人物边缘；此处只测几何，不检查或重绘人物内容。
- 图文侧排时检查正文区域中贯穿多行的空白中缝。若存在明显空洞，先移动/放大/重排现有插画，或调整文字列宽及景别，不能放一条色块掩盖。图片轮廓允许有凹凸，短行的行尾空白不要求强行填满。
- 先用脚本或当前工具的等效能力测量字体渲染后的字形 alpha 和图片 alpha 范围；中文与英文混排不只依赖字体 API 的 bounding-box 数值，以免漏算后续字形。再按命名约束检查对齐、组间距和主要图文列沟；文字测量是估算，不等同飞书实际字形，最后必须看目标端截图。
- 明确有意留白的作用：阅读入口、信息分隔、视线通道、裁切余地；不得用“极简”解释所有空洞，也不以统一占满率塞装饰。

计划写入 spacing_system（最多四档主数值）和非空 layout_constraints（对齐、组内/组间、图文列沟及测量依据）。侧排图文页必须给主要正文组与图像的 gutter 写对象 ID、basis=ink 和光学范围；960×540 下可先以16–80检查常规侧排，具体范围由构图解释，不能看到超限后只放宽范围。主间距允许约±4的光学校正，需记录原因；不能每个对象另选一个随意数值。修改一组后联动同级组，而非单点移动。

## 原生文字表现手法

文字排版不仅是换字体。每套确定主机制，普通页每页通常一个主机制，可配一个轻量辅助；同功能同样式，不能把所有参考效果堆在一页。

| 机制 | 信息用途 | 原生实现与边界 |
|---|---|---|
| 主数字与标题组合 | 核心数量、方法总数、章节入口 | 数字可占主要视觉面积并使用主色；先保证“数字—单位—标题”连续可读，单位靠近数字或标题，不拆成远离的碎片。与抬头/内容组建立对齐，同时安排其他区域视觉重量；不固定右上角、小字号或淡色 |
| 低对比背景数字 | 辅助页码、章节氛围 | 仅辅助时用淡色并标记 decorative_reason，不盖正文，不承担唯一的数量说明 |
| 胶囊标签 | 类别、状态、方法入口、案例标识 | 圆角形状和文字独立，内部留一致 padding；短标签，不能把整段正文塞成按钮 |
| 关键词/短句强调 | 核心动作或结论 | 同一强调色、字重或原生底色标记，控制数量；不是每行都加粗变色 |
| 分层说明 | 标题、组标题、正文、注释 | 固定角色样式和级差，例如44/25/18/13；用正文、说明与少量语义强调色建立层级，按项目色板保持对比 |
| 语义色面/细框 | 对照、范围、摘要 | 原生内容框默认小圆角，同级框共用半径；960×540 可从16–22起步，紧凑元素相应减小。胶囊保留半高圆角，关键词底色不强行变按钮；不为圆角改动尺寸、位置或内边距，不拿背板填空 |
| 对话与证据标注 | 角色发言、检查对象、操作提示 | 短句放原生圆角对话框，尾部指向说话者；关键词高亮与箭头指向截图里的具体区域。线头、目标轮廓和句义一致，不穿正文；截图裁切/缩放后同步映射 |

先把对齐和间距修好，再叠加原生文字样式。辅助背景数字放后层并降低对比；主数字可饱和、放大或与角色穿插，但关键笔画与阅读顺序必须清晰。两种用途不能混为固定淡色装饰；普通文字仍不得意外互相遮挡。用户要求保留正文时，样式层不改文字与事实。

## 根据真实内容量分配图文

图像主导页面可以保留，不因出现信息页而统一改成文字海报。先统计必须表达的要点、对比维度和说明深度，再分配版面；文字与图片的占比是内容的结果，不预设固定图文面积配额。

- 信息少：允许大场景、多人关系或特写作为主视觉，配少量原生文字。
- 信息较多：优先用分组标题、成对比较、步骤、信息模块等原生结构容纳真实正文；插画保留中等体量的半身、单侧场景或带动作的局部，解释主题。文字区变大时重新构图，不只是缩小上一页图片。
- 信息超出一页的舒适容量：按逻辑拆页，不靠无限缩字或删关键说明容纳。资料型可略密，但正文仍需可读。
- 纯文字大字海报是独立设计选择，只有用户明确要这种形式或内容确实适配时使用；不能把“文字较多”理解为“同样几句话放大”。

同套自然包含不同内容密度。展示高信息量样页时，选真实说明更丰富的内容段落，不强制复用原先少字封面做占比实验，也不为凑密度扩写空话。每页计划记录实际正文量、要点数、文字区、场景区、所需景别和图文接触关系；visual_priority 仅描述设计结果。

## 整套版式组织

按页面的信息关系选择构图，以下是可组合的语法，不是每套必须集齐的配额；字体、页数和配色按角色与内容确定；蓝系仅作无输入时的默认候选，不固定宋体或16页。

| 页面任务 | 图文关系与景别 | 原生信息组织 |
|---|---|---|
| 引入主题 | 左图右文、跨区标题、大近景或横向多人场景，依内容选择 | 大标题、短副题与图像共享明确对齐关系，保留阅读入口 |
| 总览路径 | 主数字/文字、物件或局部手势，可无人物 | 总数量与标题连读；下方步骤/分组呼应主视觉，不把数字孤立到角落 |
| 多种方向 | 中等体量半身角色解释任务 | 两行分组或矩阵，给出真实说明，不只放关键词 |
| 身份/情境比较 | 对等大小的两场景，人物关系直接表现差别 | 对齐的双列标题与解释 |
| 资产/组成 | 多框/色面为主，角色倚靠其中一个框，或多人操作共同物件 | 主模块与并列子模块共享网格；角色接触框沿并指向相关信息，框不必占满同一高度 |
| 操作证据 | 真实截图占据主要区域，手机或薄屏幕框沿边出血 | 邻近标签概括输入、操作对象与结果；保留关键上下文 |
| 前后对照 | 同景别、同缩放的两张真实截图，可用双手机 | 对齐的前后标签和判断说明，避免夸大修复效果 |
| 返修/收束 | 聚焦操作的大半身、手部细节或角色近景 | 步骤正文或可执行清单，收回全套主线 |

信息页可有较多正文，但每组说明有具体作用；需要补密度时回到原文补足原因、条件与操作，不编造事实，不靠放大少量文字填版。背景大数字、胶囊与强调色沿用语义，同套重复的是视觉语言，不是固定左右分区。

## 图形体量与景别

每页联合记录可见宽高、位置、人数、景别、轮廓和文字区关系。细长全身即使接近全高也可能弱；宽半身、双人桌面场景、巨大近景可以承担更大视觉重量。禁止以单一页高百分比决定 hero/support。

| 叙事任务 | 人物/场景选择 | 构图机制 |
|---|---|---|
| 创作/协作封面 | 双人或多人半身 + 桌面/设备 | 横向场景占据主区域，与标题交错或共用基线 |
| 身份/状态比较 | 两个对等景别的角色/场景 | 原生双列标题和解释，人物动作直接显示差别 |
| 情绪/观点 | 单人大半身/面部近景/身体局部 | 特写成为大色块，文字进入其留出的负空间 |
| 组成/资产/系统 | 多场景或人物操作物件 | 原生模块展示信息关系，人物/手势参与选择和组合 |
| 多人关系 | 2–4 人协作/冲突/对话 | 视线、手势、共同物件把人连成场景，不并排贴头像 |
| 步骤/数据 | 局部手势、小角色或无人 | 流程/图表主导，插画只指认关键内容 |

同套按内容变化景别和结构；不要求每三页凑齐全身/半身/近景，但不得连续靠同一全身站姿换左右。多人是可选叙事能力，不是每页添加陪衬的理由。

## 破框与语义接触

跨信息色面、人物遮断框线、手扶数字/框沿、局部从画布边缘进入、人物在物件前后穿插均可。角色倚靠内容框时先确定框顶高度和接触点，生成趴靠/扶沿/指认动作；原生框顶与前臂/手掌实际落点吻合，指向具体信息。不要生成自带另一个盒子的角色再贴到大框上。半身下缘放在有意义的前景后方或出血至页边，不在页面中间突然截断而悬空。角色、截图和设备允许有意超出画布，导出在页面边缘裁切。先选裁切边、完整对象位置与画内可见区域；优先裁掉角色下身、道具边缘或设备底座，保留脸、语义动作和截图关键内容。出血对象逐项声明 bleed_objects（字段见交付协议），未声明的越界仍需修复。复杂遮挡用分层素材，只有单张 PNG 时选择可单层实现的构图；正文不被遮挡。

## 真实截图与设备外框

先判断展示目的：手机界面默认配 iPhone，桌面界面和作为屏幕作品展示的完整横屏案例默认配薄 MacBook；局部细节、前后对照、已有框等按样机协议记录例外。竖幅视频按展示语义判断，不只看比例。设备外框是展示容器，不代表原截图来自该设备。真实界面、文字和数值不得由生图重造。没有真实截图时先找已提供的源素材；仍缺少时明确用占位，不伪造操作证据。

截图独立于设备框，保持比例，默认 cover 铺满屏幕，记录原文件、尺寸与裁切区域；先保护讲解所需的界面上下文，再裁去多余区域。若默认居中裁切会丢失证据，移动源裁切窗口或更换合适的容器/细节布局，不以屏内黑边或空带解决比例不匹配。放大细节时用原截图局部与原生标注，不拉伸、不把关键按钮或结论裁掉。竖屏视频装入手机时不能冒充手机 App 页面。优先使用内置 iPhone / MacBook 精细模板，按 [样机协议](device-mockups.md) 读取 manifest 并套图，不现场用粗矩形拼机身。外框与屏幕分层，仍可替换截图；复杂透视仅在叙事需要时使用。

设备周围沿用页面底色，不默认加彩色背板。MacBook 默认薄屏幕框，无键盘与厚底座；需要完整设备时另选确有用途的样机视角。框线与金属细节服务设备识别，不能压过截图。

图文可以沿设备边缘分组、围绕屏幕留出的负空间排布、用短标注指向真实区域，或让设备从底边/侧边进入。先决定截图要证明什么，再选图文关系；不固定每页左文右图，也不强制每页都加人物。外框、标注、角色不能盖住所讲解的关键信息。沿用同一间距体系与字体层级，不因加设备而另起一套装饰。

## 样页验收

先缩略看整体阅读入口、体量与节奏，再按实际阅读尺寸检查字形、断行、标点、对齐、图像接缝和内容动作关系。对指定页面逐页渲染，比较参考：标题字形和字重是否有性格；最大文字与场景是否形成主次；空白是否可解释；动作/物件是否指向本页主题；不同页是否只是左右互换。检查信息较多页是否真的承载了更多必要内容，插画是否仍有动作、情境或语义；不能仅把少量文字放大、原图缩角就当适配完成。不能仅凭 JSON、页数、越界测试宣称风格达标。

## 几何测量调用

每个独立元素的对齐对象及依据写入 layout_constraints；确有独立作用的例外另记 alignment_exceptions（id、reason）。语义组可作为对齐对象，但组内也要有清晰的排列。基线与光学重心由真实渲染或人工复核，不虚报脚本支持。

对象 JSON 包含 asset_base、font_files（本机字体路径和family）、spacing_system、slides；每页 objects 是 text/image（bbox、字体或素材路径），groups 可声明信息组；layout_constraints 声明 align / gap / gutter。basis=layout 检查容器节奏，basis=ink 检查真实字形/alpha 的估算列沟；不得把两者混用。gap 可引用 token；gutter 可写 min/max 光学范围，明显超限优先改布局而非扩大范围。

测量输入应使用最终手动断行；脚本不模拟目标端自动换行。测量脚本对普通图片的未声明适配按居中 contain 估算，这不是截图排版默认值。设备截图使用 cover/源裁切后，应传入实际生成的屏幕层和显示框；不能将源图全图错误映射到裁切框。禁止用 stretch 拉伸真实截图。

```bash
node <本Skill>/scripts/measure_layout.mjs objects.json measured.json
python3 <本Skill>/scripts/audit_layout.py measured.json
```

align 用 ids、edge、tolerance；edge 支持 left/right/top/bottom/center_x/center_y，center_x 是水平居中，center_y 是垂直居中；gap/gutter 用 a/b 两个对象ID数组和 axis。图文列沟只测正文相关组的整体可见边界，不把短行正常的行尾空白逐行当缺陷。修订间距规则或检查器时，用已知故障页与修改页回归，确保前者能被定位；普通制作检查本次实际页面，不要求构造测试夹具。脚本不替代飞书截图，不保证自动美学验收。
