# 角色与场景协议

## 默认风格与用户身份

默认 `assets/default-style-reference.png` 是候选编辑插画语言/人物参考：黑白与钴蓝 `#1246F2`、概括比例、宽阔轮廓、白纸肤色、简洁五官、稀少线条、平涂。它不是用户已批准的 IP，不把参考图中的两人永远绑定到每页。默认人物可为卷发蓝衣创作者、短发白衣协作者，也可按内容选动物/场景主角。

用户提供卡通/3D/像素图时，保留身份、比例、材质和媒介；真人照片保持写实身份、年龄特征与衣着。场景风格与身份分别控制。多图标注每张的用途（身份/风格/场景），不混淆角色母图与 PPT 风格截图。

## 先从角色提取配套视觉世界

收到角色图后建立 character_profile，覆盖下面各项，不把全面分析缩成取一个衣服颜色。没有图像依据的职业、故事和环境只能是结合原稿提出的候选，不能当作人物事实；例如眼镜和衬衫本身不证明职业。

| 分析项 | 提取内容及其用途 |
|---|---|
| 身份与形体 | 脸/发型/标志、服饰、比例、轮廓和配件，区分不可改特征与可变动作 |
| 媒介与美术 | 2D/3D/像素/摄影，线条粗细、形体概括、材质、纹理、阴影、透视和细节密度；约束全部配套素材 |
| 气质与表演 | 可见神态、姿势、身体节奏，推导匹配的动作/表情范围与B/C字体组 |
| 色彩角色 | 保留角色固有色，结合指定参考分配背景、环境、文字与强调，遵循 palette_contract |
| 内容情境 | 用户设定、原稿任务与图中已有活动/道具，说明每项是观察、用户信息还是推断 |
| 环境词汇 | 与上述情境相配的地点、局部空间、支撑面及可回收元素，供独立背景与完整场景选择 |
| 道具词汇 | 角色会使用/操作/检查的物件及其造型、材质和尺度，供辅助元素、前景与互动图选择 |

办公任务可衍生办公室局部、窗边工位、连续桌面空间，配套纸笔、便签、文件夹、键盘、鼠标和显示器；具体选哪些由本页结论决定，不是每页都摆满文具。软件的真实功能、界面和品牌素材使用真实来源或原生信息，生图只承担抽象软件意象或无文字屏幕，不伪造操作证据。其他角色同样从设定与内容推导环境，不把所有IP都放进办公室。

将档案中的 observed_features、inferred_context、identity_invariants、style_rules、scene_vocabulary、prop_vocabulary 连同依据保存在项目中。每类生成资产都引用同一档案，再按页面任务选场景与物件，保持角色、独立景色与辅助元素在同一视觉世界；母图提供画风，不直接复制其中不适合本页的桌沿、底座或构图。分析摘要放入原有大纲/角色方向确认，不新增确认环节。

## 风格母图、身份母图与三视图

- 风格母图：固定线条粗细、形体概括、脸部画法、色块组织、阴影和细节密度；项目 palette_contract 决定本次色彩角色，母图的原色不能覆盖用户配色。每个项目选一张，不轮换各页生成结果。先在大纲确认环节实际展示拟用母图，用户确认后固定为本项目参考；默认资源本身的候选状态不代表每个用户已认可。
- 身份母图：固定某个人/动物的五官、发型、服饰标志和比例。可与风格图是同一张；多人图要明确目标角色。跨页不要只参考上一张输出，避免累积漂移。
- 三视图：用于明确同一角色正/侧/背面的结构和衣服。适合反复使用同一 IP、需要侧背面或大幅角度变化的任务；不为了统一画风默认先生成三视图。胸像/小表情/固定正面页通常先用现有母图。真人资料缺背面时不承诺精确复原。
- 真人身份图与插画风格图冲突时，用户要求写实就保持写实；不要把真人套成风格图中的卡通人。

每次生成前读取本地母图；调用工具时通过当前工具的参考图片/附件参数实际输入，不只口头描述。记录 reference_contract：项目内路径、sha256、角色用途、approval_status，以及每个素材实际传入的参考图列表。哈希用于确认使用的是哪张图，不证明视觉一致。

同一风格母图能降低偏差，但不能保证完全一致。用户指出漂移时，检查实际输入是否缺图/误图、风格身份冲突、角度和复杂度变化，再根据其修改请求处理；不能把自动换图重试当默认流程。

## 按媒介设计动作与表情

| 媒介 | 主要表现方法 | 需固定的身份与物理条件 |
|---|---|---|
| 2D/扁平IP | 用轮廓、身体弧线、重心与手势表演；原造型允许时用压缩伸展、局部尺度反差及五官变化 | 保留比例语言、标志部位、线条与用色；固定符号眼/无嘴设计不凭空加五官，不强加真实皮肤或3D光影 |
| 3D/玩具/黏土 | 用体积转向、头身倾斜、肢体节奏、镜头远近和物件互动；模型允许时再改变眉眼/嘴型 | 保留建模比例、材质、镜头与光向；硬壳或无可动脸不强做软脸表情，手脚、道具、投影接得上，不漂成2D贴纸 |
| 真人/摄影 | 抓拍中的迈步、转身、俯身、抓取、倚靠、协作；肩胯错位、重心转移，表情有行动动机 | 五官、年龄、发型、衣着和真实关节；保留自然皮肤，避免僵硬礼貌微笑或复制同一表情 |

动作先回答“正在完成什么，以及它如何解释本页结论”，再写姿态。可用替换检验：若换成任何一个跳跃/托手的角色都不影响理解，说明角色只在装饰，应改为比较、检查、协作、操作等有内容因果的动作，或省去角色。服装、运动或表情展示本身就是主题时，造型可以直接承担内容；其他隐喻动作需能说明与本页观点的映射，不把“更活泼”当完整提示。

表情不是单独贴上的笑脸。先定情绪起因与所处瞬间，例如“发现两份结果不同而迟疑”“终于对齐样页而松口气”，再转成可见表现：允许变化的眉眼/嘴角、头部方向、肩背、手势、重心及与他人的反应。先列 identity_invariants 与 expression_range；圆形空白眼、固定嘴型、面罩等身份标志保持原样，改用歪头、后仰、探身、抱紧道具或身体轮廓传达情绪。不能为让 IP 更有表情改变其识别特征。

规划 medium、identity_invariants、expression_range、action_verb、body_weight、hand_contact、gaze_target、expression_motivation、expression_cues、camera_angle。字段描述当前动作，不是堆形容词；实际参数按执行工具转换。平静、困惑、专注、惊喜、吃力或轻松都可以成立，取决于本页内容。不要为了摆脱僵硬给每个角色随机跳跃、统一露齿笑或做同一夸张表情。

真人也能使用有内容映射的尺度反差或拼贴空间，但身体与支撑关系保持可信，不以舞台、高台或厚底座承托人物；环境可适度夸张，真人骨骼不随意拉伸。2D和3D的动作幅度仍以原IP语言为界，而非媒介名称决定一切。动作、景别、道具、镜头与场景一起变化；简单对着读者托手、抱平板、托腮不能成为整套固定动作词库。

## 角色与造景共同解释内容

造景不是仅供真人使用的摄影布景。默认小人、用户2D IP、3D IP和真人都先确定任务对象与空间关系，再按各自媒介实现；同一人物的身份参考保持不变。以下是可按内容改编的视觉句子，不是动作配额或固定模板：

| 内容关系 | 角色、情绪与环境如何配合 |
|---|---|
| 筛选与取舍 | 角色从一组备选物件中捞出/挑出目标，身体与视线朝向选择结果；“多到不知所措”与“找到后确认”的反应有明确对象 |
| 检查与返修 | 角色探身对照两张样片，用夹具固定待改处，或两名角色一起核对；局部工作台提供支撑，专注/疑惑来自可见差异 |
| 流程与协作 | 两名角色传递同一份任务物件，或一起把模块接上轨道；前后状态、接触点和视线解释交接，不能只并排站立 |
| 信息过载与整理 | 原IP允许时用比身体更大的纸堆/缠绕线团形成困境，再用抽取、归类或解结的动作说明方法；趣味来自内容矛盾和尺度关系 |
| 结果与突破 | 角色检验已拼合的结构、跨过由步骤形成的路径或与协作者回应；惊喜/释然来自任务完成，跳跃或破框本身不代替结论 |

2D可用概括道具、线条路径与有限色面组织空间；3D可用相同材质体系的立体物件、台面与有依据的光影；真人可用真实工作物件或明确的超现实拼贴。媒介混搭需有意图，不把同一个写实房间套给所有IP，也不为每页补满环境。象征性道具不能冒充真实产品功能或数据证据。

造景按视觉系统分层准备，记录 scene_purpose、interaction_target、contact_anchor、support_relation、edge_treatment 与前后关系；互动目标对应实际资产或原生对象。角色手指的东西、脚踩的面与视线终点必须在构图中有着落；桌面、地面与家具的支撑不能只靠一条投影假装成立。不生成舞台、展台、高台、厚底座、悬浮平台或带截面底板的微缩景色。没有文字的背景、角色/道具与原生信息分别记录，复杂接触允许合成一个素材。各边在最终PPT中用自然轮廓、连续空间、合理遮挡或页边出血收尾，不能将图片硬切后悬在画内。按叙事安排安静与有张力的页面，不为追求“有意思”统一大动作。

## 先选择景别、人数、关系

- 全身用于步态、体态、空间位置；不作默认。
- 半身/胸像用于讲解、桌面创作、双人协作，宽轮廓可直接承担主视觉。
- 近景用于表情、重点和尺度反差；局部手部用于选择、指认、扶框，不能为裁切而随意切掉关键动作。
- 场景图包含角色、任务物件及必要环境。电脑/镜头/桌面是语义载体时允许一起生成；无需完整房间。
- 多人必须有可读的关系：共同看一台设备、递交物件、协作搭景、冲突对峙等。不能把几张独立人像排一排冒充场景。
- 比较页可以让两个内容角色直接登场，无需再放一个无关讲解者。

每个素材记录 subject_count、shot、semantic_role、动作/情绪、视线、身份母图、可见宽高框、裁切、接触锚点、层次、输出路径、提示词、认可状态。多人共用一个图像时仍记录各身份，不误报为可独立编辑人物。

## 生成指令骨架

```text
资产用于可编辑 PPT，只生成[单人/多人关系/局部/具体场景]，不是整页幻灯片。
参考图用途：[身份]、[媒介/画风]、[场景]，分别锁定[不变项]。
角色分析：[引用 character_profile 的身份、媒介、线条/材质、光影与气质；从场景/道具词汇选择本页需要的内容，说明其与页面任务的联系；不把推断写成人物事实]。
配色：[引用项目 palette_contract；按参考分配环境底色、物件主色和少量强调色，说明大面积与点缀关系、饱和度和冷暖；保留身份原色，不误用身份图叠加文案的颜色，不强制所有物件同色；无输入时可用内置蓝系，色号不印在画面上]。
内容含义：[角色做什么、操作/比较/检查哪个对象、这如何解释本页结论；省去角色会损失什么]。
媒介[2D/3D/真人等]，身份不变项[标志、比例、可动/不可动的五官]，表情允许范围[描述]。
景别[半身/近景/全身/场景]，角色[人数与关系]，动作[动词、重心、手/物接触、视线]，表情[情绪起因、所处瞬间与可见的脸部/身体表现]，镜头[角度与距离]。
造景作用[对本页结论的帮助]，互动目标[具体物件/原生对象]，空间[支撑面、路径、前后景]；景物与角色共享媒介、透视与光向，明确混搭时说明意图。
支撑与边缘[逐项描述承重/接触，哪些边自然收尾、被合理前景遮挡或延展到最终PPT页外；桌面/地面不可在画内突然截断悬空，不靠圆角或全图羽化伪装融合]。
不要舞台、展台、明显高台、厚底座、悬浮平台或带底板的微缩景色；不要矩形背景补丁、硬切分界或悬空桌板。正常桌椅需有支撑或按规划延展至页外，不变相生成高台。
图形体量：[横向/紧凑/大半身]，方向[描述]，留给原生信息的位置[描述]。
接触锚点与前后关系[具体描述；无则不强写]。若靠在原生内容框上：给出框顶在最终构图中的高度、手/前臂接触位置和指向内容；只生成对应角色，不另画盒子或信息框。
[透明背景/明确需要的场景背景]，必要部位完整，不绘制标题、说明、图表数据、界面文字。
不要出现任何文字和颜色色号
```

默认编辑插画减少细碎衣褶、写实渲染和无关物件；用户提供真人/复杂媒介时不强行简化身份。场景道具可在图内，信息框、标题、数字保持原生。生图不要画一整页带文案海报。

经大纲与角色方向确认后，只生成当前轮次（样稿或全稿）所需素材，直接呈现并继续排版；逐图呈现不是批准停点，需样稿的项目在可编辑代表页完成后统一确认，之前不生成剩余页素材。不主动检查或自动重绘，用户修改指令才触发再生成。可做文件/尺寸检查；布局检查只修原生排版，不能把自动风格判断藏在其中。用户素材留在执行项目，不写入通用 Skill/备份。
